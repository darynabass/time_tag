# SCRUM-5 — Реєстрація та облік працівників

## Призначення

Модуль для управління працівниками TimeTag на базі **наявних** таблиць
`employees` та `rfid_tags` у SQLite. Виконує частину завдання SCRUM-5:
реєстрація, зміна даних, пошук, деактивація облікового запису та перевірка
унікальності картки. **Не змінює** `main.py`, `database/database.py`,
структуру бази, події відвідувань або файли інших учасників.

## Файли

- `scrum5/employees.py` — бізнес-логіка та SQL-запити з параметрами.
- `scrum5/cli.py` — окрема командна демонстрація без втручання в GUI команди.
- `scrum5/__init__.py` — Python-пакет.
- `tests/test_scrum5.py` — автоматичні перевірки на тимчасовій SQLite-базі.

## Запуск на Windows у PowerShell

1. Встановити Python 3.10+.
2. Відкрити кореневу папку **клонованого** репозиторію `time_tag`.
3. Якщо база ще не створена, ініціалізувати її **штатною** функцією команди:

   ```powershell
   py -c "from database.database import create_database; create_database()"
   ```

4. Переконатися, що в корені є файл `TimeTag.db`.
5. **Для демонстрації не змінюйте спільну базу:** створіть окрему копію:

   ```powershell
   Copy-Item .\TimeTag.db .\TimeTag_scrum5_demo.db
   ```

6. Виконати приклади з прапорцем `--db` (перед назвою команди):

   ```powershell
   py -m scrum5.cli --db TimeTag_scrum5_demo.db add --name "Іван Петренко" --card TEST001
   py -m scrum5.cli --db TimeTag_scrum5_demo.db list
   py -m scrum5.cli --db TimeTag_scrum5_demo.db list --search "петренко"
   py -m scrum5.cli --db TimeTag_scrum5_demo.db edit 1 --name "Іван Коваль"
   py -m scrum5.cli --db TimeTag_scrum5_demo.db set-card 1 --card NEWCARD02
   py -m scrum5.cli --db TimeTag_scrum5_demo.db deactivate 1
   py -m scrum5.cli --db TimeTag_scrum5_demo.db activate 1
   py -m scrum5.cli --db TimeTag_scrum5_demo.db show 1
   ```

   У командах з ID `1` вказати **справжній ID**, який було виведено при
   додаванні працівника; він не обов'язково дорівнює 1.

   Якщо файл бази має інший шлях, додати `--db "C:\\path\\TimeTag.db"`
   **перед** командою `add`, `list` тощо.

## Тестування

```powershell
py -m unittest discover -s tests -p "test_scrum5.py" -v
```

Тести не змінюють робочу базу: усі використовують окремі тимчасові БД.

## Особливості реалізації

- Реєстрація працівника можлива без картки; її можна додати пізніше.
- Одна картка (`card_uid`) не може бути прив'язана до двох різних працівників.
- Заміна картки деактивує попередню, але не видаляє дані.
- Деактивація працівника також вимикає його картки. Його історія відвідувань
  залишається в `attendance` без змін.
- Після повторної активації працівника картку потрібно призначити окремо.
- Пошук імен підтримує різний регістр українських літер.
- Операції використовують транзакції; якщо прив'язка дубліката UID не
  вдається, запис про нового працівника не залишиться в базі.

## Межі SCRUM-5

Цей модуль **не** реєструє прихід/вихід (SCRUM-6), **не** перевіряє
запізнення (SCRUM-11) та **не** змінює графічний інтерфейс (SCRUM-7).
Учасник, який розробляє GUI, може викликати `EmployeeService` зі свого коду:

```python
from scrum5 import EmployeeService

service = EmployeeService()
new_id = service.add_employee("Іван Петренко", "TEST001")
print(service.get_employee(new_id))
```

**Безпека:** `role='admin'` — лише дані. Авторизація адміністратора (SCRUM-9)
має бути реалізована окремо. Цей CLI — локальна навчальна демонстрація,
не готовий захищений адміністративний інтерфейс.
